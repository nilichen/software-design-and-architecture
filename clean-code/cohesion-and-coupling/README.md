# Clean Code | Cohesion, Coupling and Where the Data Lives

This folder is the app after the fixes. **[See before vs after as one diff](https://github.com/nilichen/software-design-and-architecture/commit/14b88e19dbb1e5f619708fe00cb9bd3f57fba0da)** (switch to *Split* for side by side), or [browse the before](https://github.com/nilichen/software-design-and-architecture/tree/4842c2e5134cc894abe8aa5d5c37ac26b3b13886/clean-code/cohesion-and-coupling).

In the notes below, `before/x.py` means `x.py` in the before version and `after/x.py` the file as it is now. To run the before locally: `git switch --detach 4842c2e`, then `git switch main` to come back.

## What changed

Run either version with `python3 main.py` from its folder. Both print the same receipts, except for the two bugs marked **behaviour change**.

- **Split main() by responsibility (cohesion).** In `before/main.py` one loop builds the booking, prices it, prints the quote, takes payment and sends the emails. In `after/main.py` each job has its own function (`build_contract`, `print_quote`, `check_out`, `cancel`), and the rest moves to its own module: `rental.py` for the data, `pricing.py` for the arithmetic, `payments.py`, `events.py`, `notifications.py` and `invoices.py`. A change to the receipt no longer means reading past the payment code, and the price can be tested without running the whole day.
- **One list of `Extra` records instead of two parallel lists (cohesion).** `before/main.py` keeps `extra_names` and `extra_prices` side by side, and dropping the GPS at the desk removes only the name. `after/rental.py` stores `Extra(name, price)` and `RentalContract.remove_extra` removes both together. **Behaviour change:** booking B2 now shows the child seat at €5.00 and charges €145.00. The before charged €155.00, for a GPS the customer had given back.
- **The discount no longer changes the booking (content coupling).** `apply_discount` in `before/main.py` lowered `booking.price` in place, so the quote and the checkout each took 10% off. `RentalContract.discounted_price` in `after/rental.py` returns the new price and leaves the contract alone, so asking twice gives the same number. **Behaviour change:** booking B1 is now charged €167.53 (10% off, plus the 2% credit fee). The before charged €150.78, about 19% off.
- **No function reads the global VEHICLES (global coupling).** `compute_rental_cost` used to look the vehicle up in module-level data. Now `main.py` builds the `Vehicle` objects and passes them to `build_contract`, and `pricing.rental_cost` takes plain numbers. A test can price a made-up vehicle without patching a global (`tests/test_rental.py`).
- **numpy is gone (import coupling).** `before/main.py` imported numpy, behind a guard, only to add up a list. `after/rental.py` uses the built-in `sum`, so there's nothing extra to install and one less library that can break pricing.
- **One module talks to the payment provider (external coupling).** Before, `Booking.pay` called `card_provider.charge` and `main()` called `card_provider.refund` itself. In after, only `payments.py` imports `card_provider`. If the provider changes its API, that's the one file to edit. `card_provider.py` itself is unchanged.
- **`pay_debit` and `pay_credit` instead of a method flag (control coupling, cohesion).** `Booking.pay(card, method)` branched on a string and lived in a class that shouldn't hold card data. `payments.py` has one function per method, and the choice read from the booking data goes through the one `PAY` dict in `main.py`. A new payment method is a new function and one dict line.
- **The reminder takes two values, not a whole booking (stamp coupling to data coupling).** `send_reminder(booking)` read only the email and the pick-up date. `notifications.send_reminder(email, pickup)` asks for just those, so it doesn't depend on the booking's other fields and a test needs no booking.
- **Emails and invoices listen for events (message coupling).** Before, the checkout called `send_confirmation` and `write_invoice` directly. Now `main.py` publishes `booking_confirmed` and `booking_cancelled` through `events.py`. `notifications.py` and `invoices.py` subscribe, and none of them import each other. The message keys (`booking_id`, `email`, `amount`) are now the contract between them: rename one and the subscriber breaks, and only when the code runs.
- **Main asks the contract, and the price sits in layers (Law of Demeter, information expert).** `booking.customer.email` and `booking.customer.name` appeared four times in `before/main.py`. Now `main.py` calls `contract.customer_email()` and `contract.customer_name()`, and only `RentalContract` knows a customer is inside. The price moved to the contract too, because it holds everything the price needs: `main` calls `contract.total_price()`, the contract passes days and km to `Vehicle.price`, and the vehicle passes its own rate and free km to `pricing.rental_cost`. Each layer passes down only what the next one lacks.
